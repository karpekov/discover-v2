# Kyoto7 (twor.2009) trial: Section 6 models under four ways of handling the two residents

Generated by `python -m tist_revision.pipeline.kyoto_trial report`; do not edit. Findings are logged in `tist_revision/EXPLORATIONS.md`. Not part of the paper.

Protocol as in Section 6: clusters and supervised models are fit on continuous `FL_20` train windows (20 events, 50% overlap), tested on pre-segmented `FL_20_p` windows of 10 held-out days (same days in every variant); L1 labels (resident id removed), macro F1 over classes with ≥ 50 pool and ≥ 20 test windows. DISCOVER = MLM encoder + time-of-day histogram + SCAN (balanced); ≈100 = K 20 × 5 labels, ≈250 = K 50 × 5, all = K 50 with every pool window labeled. Mean ± std over seeds.

## Variants

| Variant | Dataset | Sensor stream | Label of an event |
|---|---|---|---|
| Merged stream | `kyotomerged` | all events, once, in time order | most recently begun activity still running |
| Resident streams | `kyotoflat` | one stream per resident (R1, R2) and one for activities without a resident id; an event is copied into the stream of every activity running at that time; windows never cross streams | the activity that put the event into the stream |
| R1 labels | `kyotoresa` | all events, once, in time order | R1's activity; else a running activity without resident id; else No_Activity |
| R2 labels | `kyotoresb` | all events, once, in time order | same for R2 |
